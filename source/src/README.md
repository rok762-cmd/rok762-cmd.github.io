# 실측 스튜디오 · 원본 구조

원본은 기능별 파일로 나뉘어 있고, `build/build.py`가 **파일 이름 순서대로** 합쳐 한 파일로 만듭니다.

- `silcheuk-studio.html`: claude.ai 페이지
- `pwa/index.html`: 앱
- `실측스튜디오_오프라인.html`: 오프라인 파일

모든 파일은 같은 전역 영역을 쓰는 일반 스크립트입니다. 순서를 바꾸지 마세요.

## 두 층으로 나뉩니다

### 계산 엔진 (00 ~ 05z) — 화면 없이 돌아가야 함
현장(job)과 제품 목록(catalog)을 받아 칸 배치·견적·부재·간섭을 계산합니다.

- 화면(DOM)이나 뒤 번호 파일에 기대면 안 됩니다.
- `tests/engine/engine.test.js`의 **경계 점검**이 엔진 파일만 불러 실제로 돌려 보고, 화면 코드에 기대면 실패합니다.

```

00-rules        ★ 현장 규칙 표 (장 폭 단위·최대 폭·쿡탑장·도어 폭·뒷턱·키큰장·EP)
01-domain       품목·장 종류·도어·상판·가전 기본값, 키큰장 자리
02-state        현장·제품 목록 저장/불러오기, 구조 마이그레이션, 배치 바꾸기
03-geometry     면별 칸 배치 (휠라·EP·코너·키큰장·뒷선반)
```

## 점검

전체 점검은 `python3 tests/run_all.py` 하나로 돌립니다.

- **빌드:** 빌드가 되는지, 모듈을 합친 결과가 결과물과 같은지 확인합니다.
- **계산 엔진 (Node, 화면 없이):**
  - 경계 점검
  - 정규격 단위 점검: 50 단위, 쿡탑장, 후드 고정, 최대 폭, 400/350 도어, 직접 폭, 작은 장
  - 견적 단위 점검: 합계, 최종 금액 맞춤, 할인, 줄 수정·빼기·추가
  - 무작위 현장 600개
- **무작위 현장에서 매번 확인하는 규칙:**
  - 폭 합계가 실측과 같은지
  - 칸이 겹치거나 밖으로 나가지 않는지
  - 50 단위, 1200 이하, 쿡탑장 규격을 지키는지
  - EP 두께가 맞는지
  - 같은 입력이면 같은 결과가 나오는지
  - 정리를 반복해도 결과가 바뀌지 않는지
  - 자리가 안 되는 현장이면 검증기가 빨간 경고를 내는지
  - 견적 숫자가 맞는지
- **브라우저:** 기능별 점검(규칙 표, EP, 견적 수정, 키큰장, 키큰장 도어, 칸 폭)과 오프라인·앱 회귀(각 20항목)를 돌립니다.

느린 경우를 찾을 때는 `node tests/engine/timing.js [개수] [시드]`를 씁니다.

## 고치는 법

1. `src/` 안의 해당 파일을 고칩니다.
2. `python3 build/build.py`로 결과물을 만듭니다.
3. `python3 tests/run_all.py`가 모두 통과하면 배포합니다.

최상위 함수·상수를 다른 파일로 옮길 때는 `python3 build/move.py 이름 --from 파일 --to 파일`을 씁니다.
